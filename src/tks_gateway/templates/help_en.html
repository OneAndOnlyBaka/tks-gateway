Quick start

  1. Select the serial port of the USB-TTL adapter at the top (↻ searches again).
  2. Click Test connection – the badge shows the firmware versions.
  3. In the Configuration tab click Load from gateway. Until then the UI only shows default values.
  4. Save a backup with Raw image (.bin).
  5. Make your changes, then click Save to gateway in the tab you changed.

Every field and column with an i symbol explains itself on hover or keyboard focus.

Connect the gateway

Connect a USB-TTL adapter set to 5 V to the RJ10 programming socket of the gateway:

RJ10 on the gateway
USB-TTL adapter (5 V)

┄┄ ✕ ┄┄
VCC – do not connect
3 · TxD gateway sends
──────▶

4 · RxD gateway receives
◀──────

  • Use the TTL output, never RS232/RS485. If you are unsure about the pin order: with the gateway powered, the two contacts with about 5 V between them are GND (1) and +5 V (2).
  • The header shows the state of the connection:

How the tool works

flowchart LR
  GW[("Gateway")] -- "Load from gateway" --> WC["Working copy
(all tabs)"]
  F["File
.json .bin .gtk .gtb"] -- "Load from file" --> WC
  WC -- "Save to gateway" --> GW
  WC -- "Save as … / Export" --> F
  • Working copy: all tabs edit one working copy on the server. Nothing reaches the gateway until you click Save to gateway. Reloading the page keeps the working copy; restarting the server/container starts with default values again.
  • Partial save: Save to gateway in the Configuration tab writes only the configuration, in the Phonebook tab only the phonebook. Unsaved changes of the other part stay in the working copy.
  • One device access at a time: while loading, saving or logging runs, the buttons that need the gateway are disabled. Progress and results appear in the status bar at the bottom.
  • Orange notice: call buttons assigned in the Log tab, by capture or in the wizard are only in the working copy. The notice says how many are not yet saved and offers Save phonebook to gateway (stop logging first).

Change settings (Configuration tab)

  • Connection type: PBX extension when the gateway is connected to a PBX or ATA, Direct line for a telephone line with a phone on TLN.
  • Times: door talk time, local and external ring time (1–120 s).
  • PIN: four digits for programming by phone – change the factory value 0000.
  • Variant switching: which of the two numbers of each phonebook entry is used (e.g. day/night).
  • Master redirect: one number for all door calls (off / delayed / immediate). A warning appears if it conflicts with the answering machine setting of an entry.
  • Factory settings resets only the configuration in the working copy; save afterwards.

Changes are taken into the working copy when you leave a field.

Edit the phonebook

  • The table shows used entries; also show free entries shows all 50.
  • Edit opens the entry: name, two numbers (variant 1/2) with answering machine option, door station 1–9, button code. Apply takes it into the working copy.
  • Numbers: up to 24 characters, digits, *, #, P (pause), F/f (flash).
  • ✕ clears an entry, Clear phonebook clears all – both only in the working copy.
  • Then Save to gateway.

Connect and test a PBX

Configuration → Connect to PBX … sets the gateway up as an extension:

  1. Connection – FRITZ!Box or other PBX; wiring and PBX setup are explained; Check and load.
  2. Who rings? – all phones at once (group call number) or a separate number per call button.
  3. Times & PIN – ring duration, door talk time, PIN.
  4. Check – list of all changes, Save to gateway.
  5. Done – Test the connection now … and operating hints.

Configuration → Test PBX … offers two tests:

  • Test 1 · PBX → gateway (no bus needed): start, call the gateway from a phone of the PBX, wait for the command tone (12–20 s), enter the code shown, hang up, click Check. The UI reads the result back and resets the variant. Wait 60 s before calling again.
  • Test 2 · Gateway → PBX (bus and a learned button needed): start, ring at the door; the checklist shows door call, known button and the dialled number; answer whether the phones rang.

Watch the bus (Log tab)

  • Start / Stop switches logging; it occupies the serial port while running.
  • Test output makes the gateway log S: 90 … – proves that logging works even without bus traffic.
  • Show filters (door calls only, receives, sends, calls); Raw data and Auto-scroll change the view; Save / Clear.
  • Door calls show the phonebook entry of the button, or Assign … for unknown buttons.
LineMeaning
E: 11 …door call (contains the button address)
E: 21 / E: 20door call accepted / call end
S: 31 …gateway opens the door
T: DIAL …gateway dials a number

Calls to the gateway and phone input are not logged. "No data for some seconds" is normal while nothing happens on the bus.

Update firmware (Firmware tab)

  1. Read shows the versions of the gateway firmware and the bus driver.
  2. Choose the file: .tsk for the gateway, .hex for the bus driver, then Transfer.
  3. The gateway firmware restarts after approx. 5 s. The bus driver is erased at the start of its transfer.

Only with a stable connection. If a transfer breaks off: check the connection, power-cycle the gateway and transfer again. Bootloader reset is only useful when the gateway is stuck in the bootloader. Firmware files are not included in this tool.

Phone codes, licenses, language

  • Phone codes tab: all codes for programming and operating the gateway by phone, including undocumented ones (e.g. opening a door: call the gateway, after the command tone # + door number).
  • Licenses tab: third-party components of this installation with license texts; Download SBOM saves a CycloneDX bill of materials.
  • EN | DE in the header switches the language; the choice is remembered in this browser.
  • Each tab has its own address (e.g. #help), dialogs close with Esc.
